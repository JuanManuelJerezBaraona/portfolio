# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev      # Next.js dev server at http://localhost:3000
npm run build    # production build (prerenders both locales and every /proyectos/[id])
npm run start    # serve the production build
npm run lint     # ESLint (eslint-config-next, flat config)
npm run cv       # prints cv/cv.html and cv/cv.en.html to public/CV-Juan-Manuel-Jerez-Baraona(-EN).pdf with headless Chrome
```

The CV is ATS-oriented on purpose (one column, real text, standard section names, ligatures off). It exists in Spanish (`cv/cv.html`) and English (`cv/cv.en.html`); change both together, run `npm run cv`, and check each still fits on one A4 page (English runs slightly longer).

There is no test suite. `npm run lint` is the only static check.

## Stack

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS v4 · Zustand · next-intl. Path alias `@/*` → `src/*`. This is a single-page personal portfolio (Chilean), in Spanish and English, deployed on Vercel.

## Architecture

**Content is data-driven, not hardcoded in components.** `src/constants/data.ts` is the single source of truth: `PERSONAL_INFO`, `TIMELINE`, `SKILLS`, `AI_PRACTICES`, `ARCHITECTURE`, `PROJECTS`, `NAV_LINKS`, `SOCIAL_LINKS`, plus `groupTechStack()`. Types for all of these live in `src/types/index.ts`. To change copy, skills, or projects, edit `data.ts` — components render from it. When adding fields, update the interface in `types/index.ts` first.

**Two languages.** Spanish is the default and lives at the root (`/`, `/proyectos/<id>`); English lives under `/en` (`localePrefix: 'as-needed'`, no language detection, so a URL always shows the same language). Routing is next-intl: `src/i18n/routing.ts`, `navigation.ts` (locale-aware `Link`/`useRouter`/`usePathname`/`getPathname`, plus `alternatesFor()` for canonical + hreflang), `request.ts`, and `src/proxy.ts` (Next 16's middleware). Every route lives under `src/app/[locale]/`. Copy comes from two places:
- **Content** (`data.ts`): each translatable field is a `Text` — a plain string when it reads the same in both languages, or an `{ es, en }` pair. Components never read the raw arrays; they call `getProjects(locale)`, `getTimeline(locale)`, etc., which resolve every pair through `inLocale()` into the plain-string types (`Project = InLocale<ProjectData>`). Edit a Spanish text and its English twin together.
- **Interface text** (headings, buttons, aria-labels): `src/i18n/messages/es.json` / `en.json`, read with `useTranslations` / `getTranslations` (`t.rich` for the `<hl>` and `<b>` tags). `es.json` types the keys (`i18n/global.ts`), and `request.ts` types `en.json` against it, so a missing English key fails the build.
Use `Link` from `@/i18n/navigation` for internal routes (it adds `/en`); `next/link` only for same-page `#hash` links. The English copy must stay as truthful as the Spanish: translate, don't embellish.

**Concept: a fluorescence microscope.** Juan Manuel is a biotechnology engineer who worked in a neurobiology lab before moving to software, and the site is built around that. The hero is a procedurally drawn neuron (`Header/Micrograph.tsx`) split into three emission channels that map to his work: C1 DAPI (blue) → frontend, C2 GFP (green) → backend, C3 mCherry (red) → IA. Keep that mapping consistent wherever the channel colors appear (Skills columns, the IA section, the Architecture layers, the logo). The logo (`ui/TagMark.tsx`) is his initials as a closing tag, `</JM>`, with `<` in C1, `/` in C2 and `>` in C3; the favicon, the CV mark and the OG card use the same three symbols.

**Truthfulness matters — recruiters will ask about everything on the page.** `TIMELINE` and project countries come from the CV in `public/`. `AI_PRACTICES` and the `ai` skills list only tools he confirmed using (Claude Code, Codex, OpenCode, GitHub Copilot, his own skills, MCP servers, Spec-Driven Development, n8n, LLM API integration). The `highlights` of the Tsoft entry in `TIMELINE` (Nuxt/Vue → Next.js migrations, legacy performance, Playwright e2e, architecture decisions) are confirmed by him; keep the CV (`cv/cv.html` and `cv/cv.en.html`) in sync with them. The project fields `role`, `summary`, `challenge` and `contributions` were seeded from descriptions and stacks and are **not independently verified**. `ARCHITECTURE` (the Architecture section) only states what the CV, his NestJS hexagonal skill and he himself confirmed: Tomaco documented in Storybook from Figma, Next.js/React with Zustand, NestJS with hexagonal layers (endpoints, use cases, HTTP services) exposed through Apigee, Strapi 5, MongoDB, Playwright, CI/CD with GitHub Actions and GitLab CI deploying to Google Cloud, and Datadog and Kibana in production. Don't add other infrastructure without asking him. His level is **semi senior** (his words); in English that's **mid-level** — it has to read clearly: `PERSONAL_INFO.title` is the large role line at the top of the hero (with a non-breaking space in "semi senior"), `PERSONAL_INFO.level` fills the "Nivel" fact in the hero and in Contact, and the metadata, the OG card and both CV headlines say it too. The `outcome` and `metrics` of each project (the "Resultado" section of the case file) are **invented placeholder estimates**, written at his request to be replaced by his real figures; until he confirms them, treat every number there as unverified. Don't add metrics, tools or claims that aren't backed by him.

**Sections** (`src/app/[locale]/page.tsx`): `Header → AboutMe (Trayectoria) → Projects → Architecture → AiProfile → Skills → Contact`.

Every section after the hero opens like a chapter: the `<section>` carries `.chapter` (a 3px rule in its color across the page and its light coming in from one top corner, alternating sides with `:nth-of-type`, plus a fainter bounce at the opposite bottom corner), and its first child is `ui/SectionCover` — "03 / 06", a short note on the right, and the section name set across the width in its color, sized with container units so the longest name (ARQUITECTURA / ARCHITECTURE) fits on a phone. The number and the name come from `NAV_LINKS`, so their order is the page order. The name comes into focus (blur → sharp) as the section enters. `SectionHeading` is just the statement (h2 + body) under the cover; there are no eyebrows anymore.

- `Projects` renders `ProjectViewer` (client; tablist of the five journey stages + the selected screenshot under a `Loupe`) on `lg+`, and `ProjectCarousel` below `lg` (client; each project is a glass slide on the microscope stage: native scroll-snap, only the centred slide is in focus, a vernier scale underneath tracks the stage through `--p`, and tapping a blurred neighbour centres it instead of following its links). `PROJECTS` order is the customer journey (Cotización → Aceptación → Pago → Acceso → Postventa); numbering and prev/next rely on it.
- `screenshots.desktop` is a list, every shot cropped to 2530×1140; `screenshots.mobile` is a list too (659×1024), paired by index with `desktop`, so the phone changes along with the desktop shot (the case file shows every phone shot side by side). With more than one (today only the Landing), `ui/ShotCycle` cycles them in all three places (viewer, carousel, case file): every 2 s the current shot drifts out of focus as the next comes in, timed by a readout under the frame (pause button + one tick per shot). It holds under the mouse (so the loupe keeps its subject), off screen, and on a carousel slide out of focus; picking a shot or pausing stops it for good, and with reduced motion or without JS it never moves.
- `Architecture` ("Por dentro, la misma arquitectura") follows Projects: the layers the five apps share (from `ARCHITECTURE`, each tinted with its channel) next to a diagram of the NestJS services as three nested hexagons (domain → application → infrastructure), with Next.js coming in through an endpoint and MongoDB / other APIs reached through a repository and an HTTP service. The hexagons are an SVG capped at 22rem so its labels stay readable; it replaced an earlier section about the hero's generator code, which he judged too hard for recruiters to follow.
- `Skills` draws the stack as a well plate: one 12-well row per category, each technology a well that fluoresces in its channel color. Logos come from `simple-icons` (CC0), mapped by skill id in `Skills.tsx`; skills without a logo get a monogram.
- `src/app/[locale]/proyectos/[id]/page.tsx` statically generates one case file per project and language via `generateStaticParams`, rendered by `src/components/case/CaseFile.tsx`. `[locale]/[...rest]` sends unknown paths to the localized `not-found.tsx`.

**Layout (`src/app/[locale]/layout.tsx`)** is the root layout (`<html lang>` per locale, `NextIntlClientProvider`, per-locale metadata) with just a skip link ("Saltar al contenido", visible only on keyboard focus), `Navbar`, `main#main` and `Footer` on a flat black background. The nav items are real links (`/#section`); on the home page a click scrolls instead (instantly with reduced motion) and moves focus into the section. It also injects an inline `<head>` script that forces `scrollRestoration='manual'` and scrolls to top on load, unless the URL carries a section hash (`/#projects`), in which case `ScrollReset` lands on that section instead (it also reinforces the reset after hydration), plus a `<noscript>` fallback that un-hides `.reveal` elements.

**Components** are organized one folder per section under `src/components/`, each with a barrel `index.ts`; the top-level `src/components/index.ts` re-exports the page sections. Shared pieces live in `src/components/ui/` (`Reveal`, `SectionHeading`, `Loupe`, `ShotCycle`, `ProjectMeta`, `ScrollReset`, `LocaleSwitch`, `TagMark`). Most components are server components; only `Navbar`, `ModeToggle`, `LocaleSwitch`, `ProjectViewer`, `ProjectCarousel`, `Loupe`, `ShotCycle`, `Reveal` and `ScrollReset` use `'use client'`. `LocaleSwitch` (ES / EN in the navbar) shows only the other language on phones, and below `sm` the navbar shows the `</JM>` mark without the name, so the bar fits a 360px screen. The section links need ~1040px in either language, so below `lg` they fold into the dropdown menu (which grows to the screen height and scrolls if needed), and the mode switch's label only shows from 1200px. The micrograph is server-rendered from a seeded PRNG and ships no JS; its channel toggles are checkboxes wired with CSS `:has()`.

**State:** `src/store/uiStore.ts` (Zustand) holds only UI state — mobile menu open, active section. No data fetching anywhere; everything is static.

## Styling

Tailwind v4 with a CSS-first theme in `src/app/globals.css` — no `tailwind.config`. The `@theme inline` block maps design tokens to utility colors. Use the semantic token names rather than raw hex:
- Surfaces: `void` (page), `stage`, `stage-2`; borders: `line`, `line-strong`
- Text: `text`, `muted`
- Channels: `dapi` (blue, frontend), `gfp` (green, backend and "live/selected"), `mcherry` (red, IA), `yfp` (yellow, datos)
- Sections: each top-level section has a `.sec-<id>` class (`about`, `projects`, `arquitectura`, `ia`, `skills`, `contact`) that sets `--accent` from `--sec-<id>`. Inside a section use `text-accent` / `bg-accent` for highlights and `<em className="hl">` to emphasize a word; never borrow a channel color for that. The six section colors were chosen in OKLCH at equal lightness to stay distinct from each other and from the four channels; the channels stay reserved for their meaning (frontend/backend/IA/datos, the neuron, the Sanger bases).
- Fonts: Archivo (variable, `font-sans`/`font-display`) and Martian Mono (`font-mono`). Headlines use Archivo's width axis: `h1–h3` and `.wide` run at `wdth 118`, `.display` at `wdth 125`. `.meta` is the small mono readout used for labels and metadata.

**Two looks, one set of tokens.** The navbar switch (`ui/ModeToggle.tsx`) flips the whole site between fluorescence (default: black field, channels blended with `plus-lighter`, i.e. added light) and brightfield (a stained slide: light field, channels become stains blended with `multiply`, i.e. absorbed light). The look is pure CSS: `:root:has(#mode-brightfield:checked)` redefines the tokens. With JS, the switch runs inside a View Transition (a circle of light spreading from the knob) with every CSS transition suspended via `html.mode-switching` — do not animate the tokens themselves or add color transitions that fire on the switch: transitioning variables on `:root` repaints the whole page per frame and ~160 element transitions firing at once made it stutter on iOS. JS also persists the choice (`<html data-mode="brightfield">` + localStorage, restored before paint by `MODE_INIT_SCRIPT` in `ui/scopeMode.ts`). Never hardcode a color in a component or in `globals.css` outside the token blocks, or it will break one of the two modes — use the tokens, `color-mix()`, `--glow` and `--blend`.

Base and component styles in `globals.css` live inside `@layer base` / `@layer components` so Tailwind utilities can override them — keep new rules inside a layer, since unlayered CSS beats every utility in Tailwind v4.

Avoid the generic "AI portfolio" look the redesign moved away from: no gradient text, glassmorphism cards, corner brackets, scanlines, marquees, pinging status dots or `// eyebrow` comments. Motion is deliberately limited to the hero's focus pull, content coming into focus on scroll (`.reveal`), each section cover's name coming into focus, the loupe, the desktop shots cycling in `ShotCycle`, the calcium flashes in the micrograph and the mobile carousel (slides refocusing, the phone shot drifting on a scroll-driven timeline).

## SEO / OG

OG and Twitter images are generated per language by `src/app/[locale]/opengraph-image.tsx` / `twitter-image.tsx` (prerendered via their own `generateStaticParams`, and excluded from the proxy so `/es/opengraph-image` isn't redirected), rendering `src/components/og/OgShareImage.tsx` with the `Og` messages and the micrograph exported as a standalone SVG (`micrographSvg()`). Fonts are fetched from Google Fonts as static TTF instances at build time and fall back to the default sans if the network fails. `metadataBase` comes from `NEXT_PUBLIC_SITE_URL` (falls back to the Vercel URL). Every page sets a canonical URL and `es` / `en` / `x-default` hreflang alternates through `alternatesFor()`. Per-project metadata is built in the `[id]` route's `generateMetadata`.

The favicon and the iOS home-screen icon are `src/app/icon.tsx` / `apple-icon.tsx`, both rendering `components/og/TagIcon.tsx` (`</>` as three strokes, no font, so it stays sharp at 16px). They live at the app root, outside `[locale]`, and the proxy matcher skips `/icon` and `/apple-icon` so they aren't rewritten to a locale.
