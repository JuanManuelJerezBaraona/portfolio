# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev      # Next.js dev server at http://localhost:3000
npm run build    # production build (prerenders both locales and every /proyectos/[id])
npm run start    # serve the production build
npm run lint     # ESLint (eslint-config-next, flat config)
npm run cv       # prints cv/cv.html and cv/cv.en.html to public/CV-Juan-Manuel-Jerez-Baraona(-EN).pdf with headless Chrome
```

The CV is ATS-oriented on purpose (one column, real text, standard section names, ligatures off). It exists in Spanish (`cv/cv.html`) and English (`cv/cv.en.html`); change both together, run `npm run cv`, and check each still fits on one A4 page. Each page is full, with about 4 mm to spare, so anything added has to be paid for with a cut. `mdls -name kMDItemNumberOfPages public/CV-*.pdf` reads the page count once Spotlight has caught up; to see which lines wrap, lay the HTML out in headless Chrome at 794×1123 with `--hide-scrollbars` (with the scrollbar the page measures narrower and reports wraps that don't happen in print).

There is no test suite. `npm run lint` is the only static check.

`next.config.ts` pins `turbopack.root` to this folder on purpose. Next otherwise takes the directory of the topmost lockfile it finds going up, and there is a stray `package-lock.json` in the parent folder (`~/Proyectos`), so Turbopack was resolving and watching every project next to this one. Don't remove it.

## Stack

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS v4 · Zustand · next-intl · GSAP (ScrollTrigger, loaded on demand). Path alias `@/*` → `src/*`. This is a single-page personal portfolio (Chilean), in Spanish and English, deployed on Vercel.

## Architecture

**Content is data-driven, not hardcoded in components.** `src/constants/data.ts` is the single source of truth: `PERSONAL_INFO`, `TIMELINE`, `SKILLS`, `AI_BUILDS`, `AI_PROTOCOL`, `ARCHITECTURE`, `PROJECTS`, `NAV_LINKS`, `SOCIAL_LINKS`, plus `groupTechStack()`. Types for all of these live in `src/types/index.ts`. To change copy, skills, or projects, edit `data.ts` — components render from it. When adding fields, update the interface in `types/index.ts` first.

**Two languages.** Spanish is the default and lives at the root (`/`, `/proyectos/<id>`); English lives under `/en` (`localePrefix: 'as-needed'`, no language detection, so a URL always shows the same language). Routing is next-intl: `src/i18n/routing.ts`, `navigation.ts` (locale-aware `Link`/`useRouter`/`usePathname`/`getPathname`, plus `alternatesFor()` for canonical + hreflang), `request.ts`, and `src/proxy.ts` (Next 16's middleware). Every route lives under `src/app/[locale]/`. Copy comes from two places:
- **Content** (`data.ts`): each translatable field is a `Text` — a plain string when it reads the same in both languages, or an `{ es, en }` pair. Components never read the raw arrays; they call `getProjects(locale)`, `getTimeline(locale)`, etc., which resolve every pair through `inLocale()` into the plain-string types (`Project = InLocale<ProjectData>`). Edit a Spanish text and its English twin together.
- **Interface text** (headings, buttons, aria-labels): `src/i18n/messages/es.json` / `en.json`, read with `useTranslations` / `getTranslations` (`t.rich` for the `<hl>` and `<b>` tags). The layout hands `NextIntlClientProvider` only the namespaces client components read (`CLIENT_NAMESPACES`: `Nav`, `Mode`, `Project`, `Deck`); a new client component reading another namespace must add it there. Messages are precompiled at build time (`experimental.messages.precompile` in `next.config.ts`), which keeps the ICU parser out of the client bundle and rules out `t.raw`: store lists as plain strings (the metadata `keywords` are one comma-separated string). `es.json` types the keys (`i18n/global.ts`), and `request.ts` types `en.json` against it, so a missing English key fails the build.
Use `Link` from `@/i18n/navigation` for internal routes (it adds `/en`); `next/link` only for same-page `#hash` links. The English copy must stay as truthful as the Spanish: translate, don't embellish.

**Concept: a fluorescence microscope.** Juan Manuel is a biotechnology engineer who worked in a neurobiology lab before moving to software, and the site is built around that. The hero is a procedurally drawn neuron (`Header/Micrograph.tsx`) split into three emission channels that map to his work: C1 DAPI (blue) → frontend, C2 GFP (green) → backend, C3 mCherry (red) → IA. Keep that mapping consistent wherever the channel colors appear (Skills columns, the IA section, the Architecture layers, the logo). The logo (`ui/TagMark.tsx`) is his initials as a closing tag, `</JM>`, with `<` in C1, `/` in C2 and `>` in C3; the favicon, the CV mark and the OG card use the same three symbols.

**The hero micrograph is drawn twice.** `Header/neuron.ts` is the seeded generator (the culture: branches, axons, somas, nuclei, puncta); the order of its `random()` calls *is* the image, so never add, remove or reorder one (what a renderer needs beyond the drawing, like which neuron a branch belongs to, is derived without drawing from it). `Micrograph.tsx` renders it on the server as SVG, as before. `LiveMicrograph` (client) then fetches `liveScope.ts` once the page has settled and redraws the same culture on a WebGL2 canvas as a z-stack of soft points: each neuron sits on its own plane and blurs out of the focal plane, the pointer tilts the stack, scrolling away racks the focus through it, each neuron fires on its own every few seconds, and a click fires the nearest one (the signal runs out along its dendrites, its synapses flash as it passes, and the others answer). Plain WebGL, no library: it's one draw call of points through one shader, and three.js would have added ~170 KB for it. It reads its colors from the tokens and blends like the rest of the site (added light in fluorescence, absorbed in brightfield, re-read on `scope-mode-change`). The SVG stays until the canvas has drawn its first frame (`.scope[data-live]` cross-fades them) and for good with reduced motion, data saver, no WebGL2 or no JS. The channel toggles and the solo hover drive it through uniforms. Two rules it learned the hard way: the canvas bitmap is sized from the `.scope` around it and capped (`MAX_BITMAP`), never from the canvas's own `clientWidth` (a canvas whose CSS hasn't arrived is as wide as its bitmap, so that doubles it every pass until the GPU process holds gigabytes); never put a CSS `filter` on the canvas or anything around it (`.scope-clip`, `.scope-view`, `.scope`, the hero): the defocus is done in the shader; the field's round edge is `.scope-clip`'s mask, not `.scope`'s radius (on iOS the radius didn't clip the composited canvas and SVG, which showed the square box; don't swap the mask for a clip-path or a rounded overflow), and `.scope-clip` stays still while GSAP scales `.scope-view` inside it; and the line that says a click stimulates the neuron (`Header.stimulate`) keeps its place while hidden, so nothing shifts when the live image takes over.

**Scroll scenes (`src/components/motion/`).** GSAP + ScrollTrigger, fetched by `loadGsap()` on idle so they stay out of the first-load bundle (never import `gsap` statically, and not `@gsap/react` either, which does). Rules: GSAP sets every starting state itself, so with reduced motion, without JS or if the chunk never arrives the page is complete and still; `html.scenes-on` is set while GSAP drives, and the CSS it replaces steps aside under it (the cover name's starting scale, the index's on/off bar); animate `transform`, `opacity`, `filter` or a property registered with `inherits: false` or scoped to a leaf, never a custom property on a whole section (it would restyle the subtree every frame); an element with a CSS keyframe animation (`.rise`, `.scope-field`, `.objective-ring`) can't be moved by GSAP, so scenes target a wrapper; and don't park an element with a CSS `transform` that GSAP will later animate (GSAP folds it into its own, see `.hex-wire-pulse`). iOS rules, learned from a tab that iOS killed every time the first chapter came up on a phone (bisected on the device to the hero's scrubbed leave): don't scrub the hero from JS (its copy and its field, with the WebGL canvas inside, re-rendered on every scroll frame; `ScrollTrigger` now only toggles `#home.is-leaving` and CSS transitions do the move); never scrub a `filter` from JS (WebKit repaints a script-driven filter in software on every frame; a focus pull is a one-shot CSS transition, like the cover's); and step any font axis you animate in whole units (`modifiers`, `Math.round`: every distinct `wdth`/`wght` value is a new instance of the variable font that WebKit keeps for the life of the page). After a scripted edit of several files, check the CSS the dev server actually serves: Turbopack missed one `globals.css` write that way.

## Styling

Tailwind v4 with a CSS-first theme in `src/app/globals.css` — no `tailwind.config`. The `@theme inline` block maps design tokens to utility colors. Use the semantic token names rather than raw hex:
- Surfaces: `void` (page), `stage`, `stage-2`; borders: `line`, `line-strong`
- Text: `text`, `muted`
- Channels: `dapi` (blue, frontend), `gfp` (green, backend and "live/selected"), `mcherry` (red, IA), `yfp` (yellow, datos)
- Sections: each top-level section has a `.sec-<id>` class (`about`, `projects`, `arquitectura`, `ia`, `skills`, `contact`) that sets `--accent` from `--sec-<id>`. Inside a section use `text-accent` / `bg-accent` for highlights and `<em className="hl">` to emphasize a word; never borrow a channel color for that. The six section colors were chosen in OKLCH at equal lightness to stay distinct from each other and from the four channels; the channels stay reserved for their meaning (frontend/backend/IA/datos, the neuron, the Sanger bases).
- Fonts: Archivo (variable, `font-sans`/`font-display`) and Martian Mono (`font-mono`). Headlines use Archivo's width axis: `h1–h3` and `.wide` run at `wdth 118`, `.display` at `wdth 125`. `.meta` is the small mono readout used for labels and metadata.

**Two looks, one set of tokens.** The navbar switch (`ui/ModeToggle.tsx`) flips the whole site between fluorescence (default: black field, channels blended with `plus-lighter`, i.e. added light) and brightfield (a stained slide: light field, channels become stains blended with `multiply`, i.e. absorbed light). The look is pure CSS: `:root:has(#mode-brightfield:checked)` redefines the tokens. With JS, the switch runs inside a View Transition (a circle of light spreading from the knob) with every CSS transition suspended via `html.mode-switching` — do not animate the tokens themselves or add color transitions that fire on the switch: transitioning variables on `:root` repaints the whole page per frame and ~160 element transitions firing at once made it stutter on iOS. JS also persists the choice (`<html data-mode="brightfield">` + localStorage, restored before paint by `MODE_INIT_SCRIPT` in `ui/scopeMode.ts`). Never hardcode a color in a component or in `globals.css` outside the token blocks, or it will break one of the two modes — use the tokens, `color-mix()`, `--glow` and `--blend`.

Base and component styles in `globals.css` live inside `@layer base` / `@layer components` so Tailwind utilities can override them — keep new rules inside a layer, since unlayered CSS beats every utility in Tailwind v4.

Avoid the generic "AI portfolio" look the redesign moved away from: no gradient text, glassmorphism cards, corner brackets, scanlines, marquees, pinging status dots or `// eyebrow` comments. He asked for more motion in November 2026 (interactions, micro-animations, scroll transitions, with GSAP and WebGL), so there is more of it now, but every piece is still a microscope move that says something, not decoration: the scroll scenes (the hero's field receding as it leaves (a CSS transition the scroll triggers) while the live canvas racks its own focus, each chapter's name widening on Archivo's width axis (its focus is the one-shot CSS transition), its rule drawn from the corner its light comes from, timeline entries coming into focus one by one, images acquired line by line, the project index reading the scroll, the request running through the hexagon, the protocol's edge filling, the progress line under the navbar) and the live micrograph (depth, tilt, focus, firing neurons). Still off the table: smooth-scroll hijacking, pinned or horizontal scroll sections, custom cursors, tilt or magnet cards, particle backgrounds. Besides those, motion is the hero's focus pull (the `.rise` lines sharpen from a blur at full opacity: fading them in from `opacity: 0` made Chrome count the hero text, the LCP, only once the animation ended), content coming into focus on scroll (`.reveal`), each section cover's name coming into focus, the rule drawn over the IA protocol's critical step, the desktop shots cycling in `ShotCycle`, the calcium flashes in the micrograph, the buttons' line-by-line scan and the mobile carousel (slides refocusing, the phone shot drifting on a scroll-driven timeline), and the React Bits pieces (the hero's "código" being sequenced, the objective ring turning in, the skill being typed out, the beam sweeping "Conversemos.", the 404 coming into focus).

**Hovers are a vocabulary, not one effect.** Each kind of control answers the pointer with a different microscope technique (documented next to each rule in `globals.css`, from the `HOVERS` block on): buttons are acquired line by line, as in a point-scanning microscope: three excitation lines (C1, C2, C3) run down the button and leave the acquired image behind (the secondary button fills with the section's `--accent`, the primary one, whose white is DAPI + GFP + mCherry stacked with `--bg-blend`, goes darkfield), driven by the registered `--acq` property so leaving runs the scan back up; he turned down a magnet with chromatic aberration and labels read from DNA bases, and before that the channels slipping out of register and an octagonal field diaphragm; `.link-underline` is a sequential confocal scan (C1, C2, C3, then the text color), driven by the registered `--scan` property so it reverses cleanly; arrows (`ui/Arrow`) leave through the edge they point at and come back from the opposite one; nav dots get excited; the `</JM>` brackets part; a hero channel toggle solos its layer in the micrograph; the project index rows and the case file's neighbours widen on Archivo's width axis; a well aims a plate-reader crosshair and lights its coordinate; the hexagon's rings come into focus. The mode switch is the exception on purpose: its hover only brightens the track's border (he turned down a version where the knob rotated). Don't fall back to a bare color swap for a new control: pick the technique that fits it, keep it inside `@media (hover: hover)`, give `:focus-visible` the same answer where it makes sense, make the way in slower than the way out, and animate `translate`/`scale`/`rotate` (not `transform`) on anything that also runs a keyframe animation, so the two don't fight.

## SEO / OG

OG and Twitter images are generated per language by `src/app/[locale]/opengraph-image.tsx` / `twitter-image.tsx` (prerendered via their own `generateStaticParams`, and excluded from the proxy so `/es/opengraph-image` isn't redirected), rendering `src/components/og/OgShareImage.tsx` with the `Og` messages and the micrograph exported as a standalone SVG (`micrographSvg()`). Fonts are fetched from Google Fonts as static TTF instances at build time and fall back to the default sans if the network fails. `metadataBase` comes from `NEXT_PUBLIC_SITE_URL` (falls back to the Vercel URL). Every page sets a canonical URL and `es` / `en` / `x-default` hreflang alternates through `alternatesFor()`. Per-project metadata is built in the `[id]` route's `generateMetadata`.

The favicon and the iOS home-screen icon are `src/app/icon.tsx` / `apple-icon.tsx`, both rendering `components/og/TagIcon.tsx` (`</>` as three strokes, no font, so it stays sharp at 16px). They live at the app root, outside `[locale]`, and the proxy matcher skips `/icon` and `/apple-icon` so they aren't rewritten to a locale.
